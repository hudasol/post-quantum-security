# Completeness rubric

Author: Huda Mueen. Written 2026-10-20, before any work of round 4. It measures how far the repository is from a complete, independent study, as defined below. It is scored at the start and at the end of each round, with a reason for every score. Scores are not raised for effort, only for evidence that a reader can check in the repository.

## Definition used

A research question counts as complete only when it is answered by at least two kinds of evidence that do not share an assumption, the answer carries an uncertainty, the model behind it was validated on data it was not fitted to, and its limits are written next to the result.

## Criteria and weights

| Criterion | Weight | 0 means | 10 means |
|---|---|---|---|
| Evidence coverage | 0.20 | a few sources, one core class | every operation and core class in scope has published rows read in full, with classical baselines, energy, boot and link figures |
| Model validation | 0.20 | models never compared with data | every model used for a claim is validated on data it was not fitted to, with the error shown beside each value |
| Hardware evidence | 0.20 | no measurement on any microcontroller or core design | board measurements on at least two core classes, compared with published figures |
| Reproducibility | 0.15 | numbers typed by hand | every number regenerated by script in CI, seeds and configurations stored, documents fail the build when they disagree with data |
| Review depth | 0.10 | no independent check | every new row read by two independent readers, several independent reviews with findings resolved |
| External validity | 0.15 | invented devices, generic links | real board classes, retrieved link parameters, workloads grounded in public documentation, limits of transfer stated |
