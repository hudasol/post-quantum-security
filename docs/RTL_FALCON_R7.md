# Falcon-512 per command on the RTL cores (round 7)

Author: Huda Mueen. Generated by `rtlsim/proto/parse_falcon.py` from the logs in `rtlsim/results/logs/proto_r7/`; do not edit by hand. Label: RTL simulated (cycle accurate Verilator simulation of open RISC-V cores, never Arm silicon); sizes are host measured.

## What was run

The per command design of round 6 (`docs/RTL_BASELINES.md`) with the padded Falcon-512 signature (fixed 666 B) in place of ML-DSA-44: the ground signs each MAVLink 2 COMMAND_LONG frame and the vehicle verifies it. Library: the padded Falcon-512 folder of liboqs tag 0.16.0 (`rtlsim/proto/config.sh`), a copy of PQClean that is identical to PQClean master of 2026-08-04 apart from build files. Both cores are RV32IMC without a floating point unit. Falcon signing and key generation need floating point arithmetic; the pinned clean implementation emulates it with 64 bit integer arithmetic (its `fpr` type), which is the build used here; no hardware floating point build was possible on these cores. SHAKE256 comes from mldsa-native, as for the other designs; `rtlsim/proto/check_falcon_shim.sh` shows that one key pair and five signatures are byte identical to those made with the SHAKE256 that PQClean ships (`rtlsim/results/logs/proto_r7/falcon_shim_check.txt`). Compiler, flags, start up code, stack size and the stack painting are those of round 6. The key pair is made once per image (one run), because Falcon key generation is far more expensive than signing; signing and verification run 1 times with the round 6 seed block, and run 0 also checks that a modified command and a modified signature are rejected.
