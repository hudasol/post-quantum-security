# Planner study on synthetic fleets

Author: Huda Mueen. Generated by `cd planner && python fleetstudy.py`; do not edit by hand. Label: **estimated**. Every fleet is **SYNTHETIC**: invented devices from five invented hardware classes (`planner/results/hardware_classes.csv`), seed 20261016 plus the fleet size. Not a real fleet, not measured. The planner supports planning; it is not a security guarantee.

## 4. Which implementation the thresholds assume (1000 device fleet)

The default thresholds come from stack optimised pqm4 rows (hand written assembly; `docs/PLANNER_RULES.md`). The second line uses this repository's own portable C build as run in the emulator (`bench/mcu/qemu_results/`), which needs far more RAM. The violation count is an internal consistency check against the thresholds in force, not evidence that the code fits a real device.

## Limits

1. The hardware classes, their shares and every distribution are invented; the tornado ranking depends on them. A real inventory would change every number here.
2. The tornado moves one input at a time; interactions are not explored.
3. The tornado and section 1 use the default thresholds, which assume stack optimised assembly; with portable C thresholds (section 4) the memory inputs matter far more, so the ranking above holds only for the default assumption.
4. The staged model assumes every action in a wave succeeds and that replaced hardware leaves the fleet; it does not model budgets, downtime or partial rollouts.

_This tool supports planning. It is not a security guarantee._
