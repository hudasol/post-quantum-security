# Board predictions for the caches off pass, round 5

Author: Huda Mueen. Generated by `bench/board_kit/predictions_v5.py` from `cyclemodel/results/board_predictions.csv` (label: modelled) before any board session and before any caches off image has run on a board. The SHA-256 of this file as committed is in `docs/PREDICTIONS_V5_BOARD.md.sha256`; the file is never edited after the hash is taken. `docs/PREDICTIONS_V4_BOARD.md` stays as registered and is scored under its own rules and notes.

## What the model assumes

The cycle model of `cyclemodel/` is used exactly as in round 4: the same traces, the same non negative least squares fit on the training half of the published pqm4 rows (seed 20261020), the same reduced fit, and the same intervals. Running `python3 cyclemodel/analyse.py` regenerates its input file byte for byte. Its conditions: a Cortex-M4 at zero flash wait states with no cache and no bus contention, and code built with arm-none-eabi-gcc 13.2.1. Test half error of the full fit: median absolute 1.05 percent over 27 rows, worst 22.8 percent (`cyclemodel/results/error_summary.csv`).

Two further assumptions apply here and are not tested by the model itself:

1. **Caches off pass.** The predictions describe the images built with `-DBENCH_CACHE_OFF` (`bench/board_kit/b1/b1_main.c`), which switch the instruction cache, data cache and prefetch off at zero wait states after the clock set up. The rows the model was fitted on were measured by pqm4 with caches and prefetch on (`docs/PREDICTIONS_V4_BOARD_NOTES.md` note 9), so a board mean below a prediction may come from that and not from the model.
2. **Cortex-M33 board.** For NUCLEO-L552ZE-Q the Cortex-M4 per class costs are applied unchanged to the instruction mix traced from the Cortex-M4 build of the same source. This assumes that the Cortex-M33 has the same cost per instruction class and that its build (`-mcpu=cortex-m33`) executes the same mix. Neither is sourced; the M33 rows test whether the Cortex-M4 model transfers, not the model on its own core. The board runs at its 4 MHz reset clock with the flash latency read back (zero expected) and the instruction cache (ICACHE) off.

## Which rows are in sample

All 36 rows predict the repository harness (mlkem-native and mldsa-native v2.0.0, -O2), which the model was never fitted on: 36 of 36 rows are out of sample (`cyclemodel/results/split.csv` holds only pqm4 binaries). 36 of 36 rows carry extrapolation flags (the harness mix lies outside the training mix for at least one instruction class). The six in sample pqm4 m4f rows of round 4 (BP22 to BP24, BP28 to BP30) are B0 images, which run in the caches on pass only; they are not registered here.

## Statistic and verdicts

Each prediction is a mean over messages, so each verdict uses the board mean of all iterations of all power cycles of the caches off image; the median and spread are reported beside it, and the number of signing messages is stated because signing is skewed by rejection sampling. A row is a hit if the board mean lies inside its interval, a miss otherwise. Misses stay.

## Refutation rules (out of sample rows only; applied per board)

1. The model is refuted for a board if more than a third of its 18 rows miss (more than 6).
2. It is also refuted for a board if more than four fifths of the signed errors (board mean minus prediction) share one sign (more than 14 of 18).
3. A row counts only if its log shows `cache_pass,off`, `cache_off_applied,1` and `flash_ws,0` (parse.py turns each into a check). If no row of a board can be measured that way, the rules are not applied for that board and the session is reported as a check of conditions only.
4. For NUCLEO-L552ZE-Q a refutation means that the Cortex-M4 model does not transfer to this Cortex-M33 board; it is reported separately and does not refute the model on the Cortex-M4 board.
