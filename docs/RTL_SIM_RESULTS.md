# RTL simulated cycle counts on the Ibex RISC-V core

Author: Huda Mueen. Generated by `rtlsim/report.py`; do not edit by hand. Every number below is read from `rtlsim/results/logs/*.log`, `rtlsim/results/environment.txt` or `data/evidence.csv` by that script.

## What this is, and what it is not

These figures carry the label **RTL simulated**. They are cycle accurate counts from a Verilator simulation of the register transfer level design of lowRISC Ibex, an open source 32 bit RISC-V core. They are not measurements of Arm silicon, not measurements of any fabricated chip, and not measurements of any board. No clock frequency, energy or power figure is implied. The counts are only as faithful as the memory model described below, which is idealised.

## Configuration

- Core source: lowRISC Ibex, commit `1b29dae8866e6c0f0a3cd9dead53a77b4f45e357` (`v2.1.0-242-g1b29dae8`), licence Apache License Version 2.0. No release tag newer than v2.1.0 exists, so a recorded master commit is used.
- Core configuration: Ibex simple system, named configuration 'small': RV32IMC (RV32Zca), RV32M=RV32MFast, RV32B none, register file RegFileFF, BranchTargetALU=0, WritebackStage=0 (two stage pipeline), no instruction cache, no branch predictor, SecureIbex=0, PMP off. FuseSoC options: `--BaseIsa=ibex_pkg::BaseIsaRV32I --RV32E=0 --RV32M=ibex_pkg::RV32MFast --RV32B=ibex_pkg::RV32BNone --RV32ZC=ibex_pkg::RV32Zca --RegFile=ibex_pkg::RegFileFF --BranchTargetALU=0 --WritebackStage=0 --ICache=0 --ICacheECC=0 --ICacheScramble=0 --BranchPredictor=0 --DbgTriggerEn=0 --SecureIbex=0 --PMPEnable=0 --PMPGranularity=0 --PMPNumRegions=4 --MHPMCounterNum=0 --MHPMCounterWidth=40`. The comment for this configuration in `ibex_configs.yaml` describes a two stage pipeline with a 3 cycle multiplier (4 cycles for mulh). It was chosen because it is the documented configuration closest to a small microcontroller class core.
- Memory model: single 1 MB dual port RAM shared by instruction and data ports; read data returned the cycle after the request (ram_2p), INSTR_CYCLE_DELAY=0, no wait states, no cache, no flash model. The RTL RAM size is `Depth(1024*1024/4) words of 32 bits` (1 MB) and was not changed. The stock link script uses only part of it, so `rtlsim/build_sw.sh` generates a link script with 0x100000 length 0xC0000; stack 0x1C0000 length 0x40000. A real microcontroller fetching from flash with wait states would take more cycles.
- Simulator: Verilator 5.020 2024-01-01 rev (Debian 5.020-1); FuseSoC 2.4.3. The Ibex README recommends building Verilator from source because packaged versions are often too old; the packaged version was used here. It passed the Ibex tool check (minimum 4.210 in util/tool_requirements.py) but is not the version pinned by Ibex CI (v4.210 in ci/vars.env).
- Compiler: riscv64-unknown-elf-gcc (13.2.0-11ubuntu1+12) 13.2.0; flags `-march=rv32imc_zicsr -mabi=ilp32 -O3 -fomit-frame-pointer -static -mcmodel=medany -ffreestanding -fno-builtin-printf -std=gnu99`; C library picolibc rv32im/ilp32 (1.8.6-2) for memcpy, memset and memcmp.
- Libraries (portable C backends, default configuration, no native backend): mlkem-native `d1b2fe782888bdb761a50336012923180be7f502 v2.0.0` and mldsa-native `834a90d5e846ffa1e1611bd24e160bb2e9b86d35 v2.0.0`; licence Apache-2.0 OR ISC OR MIT (library sources, per LICENSE).
- Randomness: a fixed seed generator (splitmix64, seed 20261020) in `rtlsim/sw/bench_rng.c`. It is insecure by design and exists only so that runs are repeatable.
- Timing: the `mcycle` CSR is read immediately before and after each call; the cost of two back to back reads (from the log) is subtracted. ML-KEM runs keygen, encaps and decaps five times each. ML-DSA runs keygen once, then sign and verify on five distinct 64 byte messages with an empty context string.
- Checks: decaps must return the encaps shared secret; verify must accept each signature; verify must reject the first signature after one message bit is flipped (not timed, first run only).

## Reproduce

```
bash rtlsim/fetch.sh        # clone Ibex, mlkem-native, mldsa-native at pinned commits outside the repository
bash rtlsim/build_sim.sh    # build the Verilator model, configuration small
bash rtlsim/build_sw.sh     # build one ELF per parameter set
bash rtlsim/run.sh          # run all six; logs go to rtlsim/results/logs
bash rtlsim/record_env.sh   # record versions and commits
python3 rtlsim/report.py    # write the CSV files and this document
```

Outputs: `rtlsim/results/ibex_cycles.csv` (label, configuration, compiler, flags, library commit, operation, statistic, cycles, correctness) and `rtlsim/results/ibex_vs_cortex_m4.csv` (comparison, published values in columns suffixed `_published`).
