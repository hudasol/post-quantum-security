## Before the session (at home)

1. `python3 bench/board_kit/build_b0.py --platform nucleo-l4r5zi`, `python3 bench/board_kit/build_b1.py --platform nucleo-l4r5zi --cache both` and `python3 bench/board_kit/build_b1.py --platform nucleo-l552ze-q --cache both` (all clone at the pins outside the repository and stop on a commit mismatch). Then `make_build_log.py`.
2. Check that the caches off option is compiled in: `python3 bench/board_kit/cache_check.py <elf> --platform <platform> --expect off` on every `_cacheoff` image and `--expect on` on the others (the unit tests do this for every image found).
3. Dry run: `build_b0.py` and `build_b1.py --cache both` with `--platform mps2-an386`, then `run_dry_run.py`; it must report 0 unrecognised lines and 0 failed checks for both passes.
4. Install a free flash tool: OpenOCD (pqm4 uses `openocd -f st_nucleo_l4r5.cfg -c "program <image>.hex verify reset exit"`; for the L552 board use OpenOCD's `board/st_nucleo_l5.cfg` if the installed OpenOCD has it, else STM32CubeProgrammer's free command line tool) or `st-flash`; install pyserial. No vendor login.
5. Copy `$WORK/board_kit_out/` and the pqm4 clone to the laptop; record `arm-none-eabi-gcc --version` and the repository commit.

## At each board

1. Record board name, chip marking and ST-LINK firmware version. The ST-LINK virtual COM port carries LPUART1 at 38400 baud on both boards (pqm4 setting; UM2581 for the L552 board).
2. Board check first: flash `b1_mlkem_512_cacheoff.hex`. Its META lines give `cache_pass` (off), `cache_off_applied` (must be 1), the clock (`clock_hz_rcc`), `flash_ws` (must be 0) and `cache` (all enable bits 0), and the counter check (`counter_dwt_cycles` against `counter_systick_cycles`). Stop if the counters disagree. Then flash `b1_mlkem_512.hex` and check that `cache` shows the enable bits set.
3. Optional cross check with OpenOCD on nucleo-l4r5zi: `mdw 0x40022000` (FLASH_ACR), `mdw 0x40021008` (RCC_CFGR), `mdw 0x4002100c` (RCC_PLLCFGR); on nucleo-l552ze-q `mdw 0x40022000` (FLASH_ACR) and `mdw 0x40030400` (ICACHE_CR); addresses from the pinned libopencm3 and CMSIS headers.
4. Pass the read back values to `parse.py` for B0 (`--clock-hz --flash-ws --cache --toolchain --commit`).

## Runs

1. Start `capture.py --port <port> --board <NUCLEO-L4R5ZI|NUCLEO-L552ZE-Q> --run <n> --image <name> --experiment B0|B1 --label "board measured" --out <log>` before each flash or reset; it stops at `#`.
2. Harness images (B1, both passes) and speed images (B0): flash once, then 3 power cycles, one capture per power cycle with `--run 1`, `2`, `3`. Iterations per run: B1 100 on nucleo-l4r5zi and 20 on nucleo-l552ze-q (its clock is five times lower); B0 ML-KEM-768 100 and ML-DSA-44 1000.
3. Test and stack images: one run each. Any line starting `ERROR` stops the session.
4. Energy (`docs/BOARD_RUN_PROTOCOL.md` section 10): with the ammeter in place of the IDD jumper, one more run of the caches off images of the energy block; write one row per operation phase into a copy of `ENERGY_TEMPLATE.csv`.
5. Keep every raw log; never edit one.

## After

1. `parse.py <logs> --out board.csv --checks-out checks.csv --require-all [--energy energy.csv]` (exit 0 needed; the caches off check fails if a caches off image did not apply its writes).
2. `compare.py board.csv --checks checks.csv --out compare.csv`: groups are kept apart by board and cache pass; `model_conditions` says which rows meet the model's conditions. Score `docs/PREDICTIONS_V5_BOARD.md` with `score_v5_board.py board.csv --checks checks.csv --out score_v5_board.csv` (caches off rows only, rules 1 to 4 per board).
3. Report board measured numbers in their own table, labelled board measured, with board, clock, flash wait states, cache bits, cache pass, toolchain and commit. Never merge them into published, emulated or modelled columns. Copy logs and commands to `bench/mcu/board_results/<date>/` (`ONE_AFTERNOON.md` gives the commands).
