# Board session checklist (NUCLEO-L4R5ZI, B0 and B1)

Author: Huda Mueen. Status: **planned**. Generated by `bench/board_kit/session_plan.py`. Estimated session length (label estimated): **109 minutes** (B0 65, B1 29, set up 15); longest step mupq_pqclean_crypto_sign_ml-dsa-44_clean_speed at 32 minutes. Assumed, not sourced: 20.0 s per flash, 30.0 s per power cycle. Cycle inputs: published pqm4 means at 20 MHz; B1 uses pqm4 clean as a stand in. Details: `session_plan.csv`.

## Before the session (at home)

1. `python3 bench/board_kit/build_b0.py --platform nucleo-l4r5zi` and `python3 bench/board_kit/build_b1.py --platform nucleo-l4r5zi` (both clone at the pins outside the repository and stop on a commit mismatch). Then `make_build_log.py`.
2. Dry run: `build_b0.py` and `build_b1.py` with `--platform mps2-an386`, then `run_dry_run.py`; it must report 0 unrecognised lines and 0 failed checks.
3. Install a free flash tool: OpenOCD (pqm4 uses `openocd -f st_nucleo_l4r5.cfg -c "program <image>.hex verify reset exit"`) or `st-flash`; install pyserial. No vendor login. Write and hash the prediction file (protocol section 9).
4. Copy `$WORK/board_kit_out/nucleo-l4r5zi/` and the pqm4 clone to the laptop; record `arm-none-eabi-gcc --version` and the repository commit.

## At the board

1. Record board name, chip marking and ST-LINK firmware version. The ST-LINK virtual COM port carries LPUART1 at 38400 baud (pqm4 setting).
2. Board check first: flash `b1_mlkem_512.hex`. Its META lines read back the clock (`clock_hz_rcc` from RCC registers after pqm4's `hal_setup(CLOCK_BENCHMARK)`), `flash_ws`, `cache` (icache, dcache, prefetch) and run the counter check (`counter_dwt_cycles` against `counter_systick_cycles`). Stop if the two counters disagree, if the clock is not 20000000, or if `flash_ws` is not 0. The same pqm4 set up code runs in the B0 images, so these values also describe B0.
3. Optional cross check with OpenOCD: `mdw 0x40022000` (FLASH_ACR), `mdw 0x40021008` (RCC_CFGR), `mdw 0x4002100c` (RCC_PLLCFGR); addresses computed from the pinned libopencm3 l4 headers.
4. Pass the read back values to `parse.py` for B0 (`--clock-hz --flash-ws --cache --toolchain --commit`).

## Runs

1. Start `capture.py --port <port> --run <n> --image <name> --experiment B0|B1 --label "board measured" --out <log>` before each flash or reset; it stops at `#`.
2. Speed images (B0) and harness images (B1): flash once, then 3 power cycles (unplug and replug USB), one capture per power cycle with `--run 1`, `2`, `3`. Iterations per run: ML-KEM-768 100; ML-DSA-44 1000 (B0, matching pqm4's published 1000); B1 100 for every set (1000 for B1 signing does not fit the session; recorded as a deviation).
3. Test and stack images: one run each. Any line starting `ERROR` stops the session.
4. Keep every raw log; never edit one.

Note: these images run with the caches and prefetch that pqm4's set up enables, so they check conditions and reproduce published rows but cannot refute the cycle model (`docs/PREDICTIONS_V4_BOARD_NOTES.md` notes 7 to 9).

## After

1. `parse.py <logs> --out board.csv --checks-out checks.csv --require-all` (exit 0 needed).
2. `compare.py board.csv --out compare.csv`: board measured against published by evidence id, against `cyclemodel/results/board_predictions.csv` if present, and RTL simulated rows if present; ratios carry bootstrap 95 percent intervals (seed 20261020).
3. Report board measured numbers in their own table, labelled board measured, with board, clock, flash wait states, cache bits, toolchain and commit. Never merge them into published, emulated or modelled columns. Copy logs and commands to `bench/mcu/board_results/<date>/`.
