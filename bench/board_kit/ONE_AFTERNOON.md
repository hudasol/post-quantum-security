# One afternoon at the bench (plan for the person at the bench)

Author: Huda Mueen. Status: **planned**. Generated by `bench/board_kit/session_plan.py` from `session_plan.csv`; every time below is estimated (published cycle counts as stand ins, assumed handling times). The plan keeps whole blocks, in order, while the total stays within 180 minutes. Commands assume a shell in the repository clone with the images under `$WORK/board_kit_out/` (built at home, `CHECKLIST.md`).

## What to bring

1. NUCLEO-L4R5ZI and, if the second block fits, NUCLEO-L552ZE-Q, each with a USB cable.
2. A laptop with OpenOCD or st-flash, Python 3 with pyserial, and the repository clone.
3. For the energy block: a multimeter with a mA range and two leads with jumper sockets, or a lab power analyzer.

## Steps

1. **nucleo-l4r5zi setup** (15 minutes, 15 minutes so far). Set up the board: plug the NUCLEO into the laptop by USB and find its serial port (`/dev/ttyACM0` or similar on Linux, a COM port on Windows). Board check, once per image: start `python3 bench/board_kit/capture.py --port <port> --baud 38400 --board NUCLEO-L4R5ZI --run 0 --image b1_mlkem_512_cacheoff --experiment B1 --label "board measured" --echo --out results/<date>/nucleo-l4r5zi/check/run0_b1_mlkem_512_cacheoff.log`, then flash `b1_mlkem_512_cacheoff.hex` (the flash tool resets the board, so the capture records from the first line); then the same for `b1_mlkem_512.hex` with `--image b1_mlkem_512` and the file name `run0_b1_mlkem_512.log`. The check logs stay in `check/`, outside the cycle runs.
   Expected: META lines with `cache_pass,off`, `cache_off_applied,1`, `flash_ws,0` and all cache bits 0, then `cache_pass,on` with the enable bits set; `counter_dwt_cycles` close to `counter_systick_cycles`.
2. **nucleo-l4r5zi B1 off** (29 minutes, 44 minutes so far). Caches off pass: for each `b1_*_cacheoff.hex` image, flash once and capture three power cycles (`--run 1`, `2`, `3`).
   Images: `b1_mlkem_512_cacheoff`, `b1_mlkem_768_cacheoff`, `b1_mlkem_1024_cacheoff`, `b1_mldsa_44_cacheoff`, `b1_mldsa_65_cacheoff`, `b1_mldsa_87_cacheoff`.
   Flash each image with the tool tested at home (`CHECKLIST.md`, before the session, step 4).
   Command per image and power cycle: `python3 bench/board_kit/capture.py --port <port> --baud 38400 --board NUCLEO-L4R5ZI --run <1|2|3> --image <image> --experiment B1 --label "board measured" --out results/<date>/nucleo-l4r5zi/run<n>_<image>.log`.
   Expected: Each log ends with `#`; BENCH lines with cycles; CHECK lines with 0 failures.

   Expected: As above, with `cache_pass,on`.
4. **nucleo-l4r5zi energy** (13 minutes, 86 minutes so far). Energy: remove the IDD jumper and connect the ammeter in its place. Idle current first, one method only: hold the board's reset button down, let the meter average for 10 s, and write that value into `current_ma_idle` of every row of this board. Then rerun the listed caches off images once with `--echo`. The capture prints each line as it arrives, and an operation's phase runs while its BENCH lines (for example `BENCH,ML-KEM,ML-KEM-512,encaps,...`) scroll: restart the meter's average (its MIN, MAX and AVG mode) at the first BENCH line of an operation and read it at the first BENCH line of the next operation, or at the STACK lines after the last one. Write one row per operation phase into a copy of `ENERGY_TEMPLATE.csv` (results/<date>/energy.csv). The energy logs stay in their own folder: parse.py joins them through the cycles of the caches off pass, so they are not parsed as extra cycle runs.
   Images: `b1_mlkem_768_cacheoff`, `b1_mldsa_44_cacheoff`.
   Flash each image with the tool tested at home (`CHECKLIST.md`, before the session, step 4).
   Command per image (one run): `python3 bench/board_kit/capture.py --port <port> --baud 38400 --board NUCLEO-L4R5ZI --run 1 --image <image> --experiment B1 --echo --label "board measured" --out results/<date>/nucleo-l4r5zi/energy/run1_<image>.log`.
   Expected: One row per operation phase with supply voltage, mean current and idle current.
