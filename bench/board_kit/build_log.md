## How B0 is built (pqm4's own build, following its README at the pin)

The README at the pin says to clone with `--recursive` and build with `make -j4 PLATFORM=<platform>`, and that `benchmarks.py` builds, flashes and reads each binary. `build_b0.py` builds only the binaries needed, with the same make arguments that `benchmarks.py -p nucleo-l4r5zi` passes (read from `mupq/mupq.py` and `interface.py`): `IMPLEMENTATION_PATH`, `MUPQ_NAMESPACE` for PQClean code, `PLATFORM`, `MUPQ_ITERATIONS`, `LTO=` and `AIO=1`. pqm4's default optimisation (`-O3`) applies. `MUPQ_ITERATIONS` is a retained variable, so each iteration count gets a fresh object tree. Iterations per run: ml-kem-768 100, ml-dsa-44 1000. Variants: clean and the fastest m4f variant in pqm4's benchmarks.csv (ML-KEM-768 m4fspeed, ML-DSA-44 m4f); `--optional` adds m4fstack.

```
git clone --recursive https://github.com/mupq/pqm4.git $WORK/pqm4_kit
git -C $WORK/pqm4_kit checkout 5e5cc76d0b072ee7077e58afcbc619a1a67a53b4 && git -C $WORK/pqm4_kit submodule update --init --recursive
python3 bench/board_kit/build_b0.py --platform nucleo-l4r5zi
python3 bench/board_kit/build_b0.py --platform mps2-an386   # dry run images
```

## How B1 is built (route A: harness on pqm4's platform layer)

`build_b1.py` clones pqm4 again at the pin (`$WORK/pqm4_b1`), runs pqm4's own make rules through `b1/pqm4_platform.mk` to build libopencm3, the linker script and pqm4's HAL library (`AIO= NO_RANDOMBYTES=1`), prints pqm4's flags for the platform, and compiles the unchanged harness sources plus `b1/b1_main.c` with those flags (`-O3` replaced by `-O2`, the harness setting). Start up, clock and UART are pqm4's: libopencm3's vector table and reset handler with `common/hal-opencm3.c` on nucleo-l4r5zi, `startup_MPS2.S` with `common/hal-mps2.c` on mps2-an386. No start up, clock or UART code was written. B1 prints on LPUART1 at 38400 baud, the same port and rate as pqm4. The run id is set by `capture.py --run`, so one image serves all three power cycles.

```
python3 bench/board_kit/build_b1.py --platform nucleo-l4r5zi --cache both
python3 bench/board_kit/build_b1.py --platform mps2-an386 --cache both
```

## Round 5: cache passes and the Cortex-M33 board

`--cache both` builds every B1 set twice: the caches on image (`b1_<alg>_<set>`, unchanged) and the caches off image (`b1_<alg>_<set>_cacheoff`, `b1/b1_main.c` compiled with `-DBENCH_CACHE_OFF`). Only the glue object differs between the two. `--platform nucleo-l552ze-q` builds B1 for NUCLEO-L552ZE-Q without pqm4's platform layer, which has no Cortex-M33 board at the pin: the vendor start up file, system file and linker script of STMicroelectronics cmsis_device_l5 v1.0.7 (`e237398c0cbae890f4659f74fe6b64cae339b6a0`) and the CMSIS core headers of cmsis_core v5.9.0_20250520 (`b7487de1303e2eb77c402432e368691e9dcfb5f0`), used unchanged, plus `b1/m33/hal_l552.c` (LPUART1 at 38400 baud, SysTick time, reset clock). Flags: `-mcpu=cortex-m33 -mthumb -mfloat-abi=hard -mfpu=fpv5-sp-d16 -std=gnu99 -O2 -g3 -Wall -Wextra -Wshadow -fno-common`; iterations per run 20 for every set.

```
python3 bench/board_kit/build_b1.py --platform nucleo-l552ze-q --cache both
```
