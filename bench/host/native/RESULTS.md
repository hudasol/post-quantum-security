# Host measured baseline: mlkem-native and mldsa-native on the PC

Author: Huda Mueen. Generated by `bench/host/native/analyze_native.py` (called by `run_native.sh`). Label: **host measured**. These are nanoseconds on a PC, not microcontroller results, and they do not transfer to a microcontroller. They are used only for ratios between algorithms.

## Method

CPU: AMD Ryzen 7 7730U with Radeon Graphics; Linux 6.18.33.2-microsoft-standard-WSL2; gcc (Ubuntu 15.2.0-16ubuntu1) 15.2.0; flags -std=c99 -O2 -DBENCH_HOST (bench/mcu/Makefile host target). Same harness and library commits as the emulated runs (`config.csv`). One discarded warm up run of every binary, then 5 runs pinned to CPU 2, 220 iterations per operation per run; the first 20 iterations of every run are dropped as in process warm up. Statistic: median per run, then the median of the run medians; spread: coefficient of variation of the run medians. Frequency scaling and turbo were not controlled (no administrator rights), which is a stated limit.

## Limits

1. Different implementations: the host runs mlkem-native and mldsa-native (portable C), while the published pqm4 'clean' rows are PQClean reference code on a Cortex-M4; agreement of ranks does not mean agreement of cost.
2. A PC has caches, out of order execution and a 64 bit datapath; a Cortex-M4 has none of these, so ratios shift. That shift is why these numbers are not transferable.
3. ML-DSA signing time depends on the message (rejection sampling); the harness signs a different message each iteration, and pqm4 reports a mean, not a median.
4. CPU frequency was not fixed.
