# S5: Benchmark-plan facts (on-hardware PQC benchmarking on Cortex-M4/M33-class boards)

Stream S5, written 2026-10-11. All retrieval dates below are 2026-10-11 unless stated.
Method: deviation D1 (curl through the network proxy, TLS verification on, default curl User-Agent, no mirrors or caches). For GitHub repositories, `git clone --depth 1` worked through the proxy, so repository files were read locally from clones; GitHub HTML pages and api.github.com returned 403, and `gh api` refused ("access not enabled", a wider repository access request not used). raw.githubusercontent.com worked. Where a vendor page was blocked it is listed in section 8; no numbers from blocked pages are used.

Conventions:
- "Tag commit date" is the committer date of the commit the tag points to. It is NOT necessarily the publication date of a GitHub Release (release pages were not retrievable). The tag name is exact.
- Prices are "approximate, as seen on 2026-10-11" and are the single-unit list price shown to the crawler (shipping, VAT and currency conversion not applied; currency kept as shown).
- Board spec rows taken from Zephyr board docs are SECONDARY (project docs that transcribe vendor text). The manufacturer pages for ST, Nordic and Raspberry Pi (product pages) were blocked, except the Raspberry Pi datasheet PDFs and the ST eStore.

### 1c. Observations a benchmark author needs

1. pqm4 will be archived read-only in or after January 2027 and is Cortex-M4 only. For ML-KEM/ML-DSA it is a frozen snapshot; the maintained alternatives are mlkem-native/mldsa-native (C90 portable; Cortex-M33 cycle counting via DWT already in their test HAL).
2. For SLH-DSA on a microcontroller, pqm4 offers SPHINCS+ (round-3-style names), not FIPS 205-labelled code; slhdsa-c implements FIPS 205 but is flagged "work in progress"; wolfCrypt (`--enable-slhdsa`) also implements FIPS 205.
3. For LMS/XMSS verification: Mbed TLS/TF-PSA-Crypto (LMS verify only, enabled by default in crypto_config.h), wolfCrypt (`--enable-lms`, `--enable-xmss`) and wolfBoot (LMS/HSS, XMSS, ML-DSA image signing) are the embedded-oriented routes found; hash-sigs and xmss-reference are host-oriented references. No Cortex-M cycle benchmarks of these were read in this stream (that is S2).

## 4. Statistical practice for microbenchmarks (what the retrieved references recommend)

| Reference | What it recommends / reports | URL | Retrieved |
|---|---|---|---|
| SUPERCOP / eBACS (bench.cr.yp.to/supercop.html; current release string on page: `supercop-20261004`) | Measures cycle counter, runs computation, reads counter again, repeats, "records all the resulting measurements"; "also runs the measuring program multiple times in case there are variations from one run to another (from, e.g., randomized memory layouts)"; "Medians and quartiles are reported on the web pages (or stabilized quartiles starting with supercop-20260214), and any severe discrepancies are flagged in red." Run on an idle machine (interrupts matter if they hit 25 % or more of computations); disable hyperthreading; eBACS policy is to measure at nominal CPU frequency, i.e. disable Turbo Boost / use the `performance` governor or fix frequency via `userspace`/`no_turbo`; machines with cooling problems are marked unstable; prefer a real cycle counter (rdpmc or ARM cycle-counting coprocessor instructions). | https://bench.cr.yp.to/supercop.html ; https://bench.cr.yp.to/tips.html | 2026-10-11 |
| pqm4 (README, see section 3b) | Min/avg/max over 100 executions (fewer for slow schemes, number shown), fixed low clock to avoid flash wait states, and an explicit hint to repeat benchmarks for schemes with variable execution time. Observed in benchmarks.md: executions listed as 10 or 1000 per row. | https://github.com/mupq/pqm4 | 2026-10-11 |
| Riou, Park, Anwar, Poschmann, Hutter, "Apples, Oranges, and Signatures: Pitfalls and Methodology in ML-DSA Benchmarking", IACR ePrint 2026/1333 (last updated 2026-07-06; published in Springer CCIS) | Abstract only (the PDF returned 403 from Cloudflare; the ePrint abstract page and search page are retrievable). Abstract states: ML-DSA signing time variability (rejection sampling and other data-dependent components) "makes commonly used straightforward metrics, e.g., min/average/max, unsuitable for migration planning"; proposes "standardized input data sets and clearly qualified reporting metrics" and WCET-oriented assessment; also mentions pitfalls in comparing security levels. Body text not read, so I cannot report their exact percentile recommendation. | https://eprint.iacr.org/2026/1333 | 2026-10-11 |
| Google Benchmark "Reducing Variance" (general microbenchmark guidance, not crypto-specific) | Disable CPU frequency scaling (`cpupower frequency-set --governor performance`), disable ASLR, pin to a core; lists sources of variance: heterogeneous cores, Turbo Boost/Precision Boost, context switching, SMT, cache effects from other cores. | https://google.github.io/benchmark/reducing_variance.html | 2026-10-11 |

What this implies for the user's benchmark plan (my synthesis; each point maps to a source row above): report medians and quartiles (or percentiles) rather than only mean; for ML-DSA signing, publish the full distribution or high percentiles and the fixed input set, because min/avg/max are flagged as unsuitable; record the number of runs; fix the MCU clock and flash wait states, and state both; keep the machine idle (on an MCU: disable unrelated interrupts, note any SysTick/ISR overhead); repeat runs across power cycles to catch run-to-run variation.

## 7. Gaps and discrepancies worth knowing

1. pqm4 README says all cycle counts were taken at 24 MHz; the L4R5ZI (default board) benchmark clock in code is 20 MHz. The `benchmarks.md` header does not name the board. Do not cite pqm4 table numbers as "24 MHz" without checking which board produced them.
2. pqm4 has no Cortex-M33 support (libopencm3 has a `u5` dir but pqm4's mk files only cover L4R5, L476, F4, F3, F415 and the MPS2 M4 target). For an M33 board the user needs another harness (mlkem-native/mldsa-native test HAL with DWT, or Zephyr-based).
3. pqm4 times with SysTick (24-bit, ISR-extended), not DWT; if the user uses DWT CYCCNT on her own harness, results are comparable only after noting the different counter and overheads.
4. PQClean and soon pqm4 are retired/archived; versions pinned by commit hash are the only reproducible reference.
5. Zephyr's own `liboqs` doc says Zephyr 3.4/3.5 supported; Zephyr 4.4.2 itself ships only experimental mldsa-native (ML-DSA-87, internal driver) and Mbed TLS LMS verify.
6. wolfSSL and wolfBoot are GPLv3 (commercial licence otherwise); liboqs MIT; mlkem-native/mldsa-native Apache-2.0 OR ISC OR MIT; Mbed TLS/TF-PSA-Crypto Apache-2.0 OR GPL-2.0-or-later.
